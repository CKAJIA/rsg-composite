# rsg-composite

Отдельная версия ресурса с раздельными путями спавна растений и яиц.

## Установка

1. Скопируйте папку `rsg-composite` в каталог ресурсов сервера.
2. Отключите старый `rsg-composite`, затем добавьте `ensure rsg-composite` в конфигурацию сервера.
3. Убедитесь, что установлены зависимости `rsg-core`, `ox_lib` и `oxmysql`.

Таблица `player_composites` хранит собранные точки персонажей между перезаходами. Она создаётся автоматически при старте ресурса; SQL-шаблон находится в `install/player_composites.sql`. Записи очищаются ежедневно в 06:00 по времени сервера и при ручной остановке или перезапуске ресурса, например для тестирования или устранения ошибок.

Обе версии регистрируют одни и те же usable items, поэтому не запускайте их одновременно: обработчик предмета может быть перезаписан одним из ресурсов.

## Что изменено

- Растения и яйца проходят через отдельные функции спавна; создание композита по-прежнему выполняет известный native `_CREATE_HERB_COMPOSITES`.
- Вариант гаторьей кладки выбирается случайно (3, 4 или 5 яиц), а количество награды берётся из ID выбранного варианта.
- Перед каждым native-вызовом проверяется общий лимит в 180 композитов. Учитываются только успешные ID; невалидный ID не передаётся в удаление.
- Спавн прекращается, если composite-ассет не загрузился.
- Исправлены верхняя граница количества слотов и расчёт X/Y по одному углу в радианах.
- Смещения древесных орхидей вынесены в таблицу по ID ресурса и сверены по названиям с оригиналом; для ванильного цветка сохранено отдельное смещение. Древесные орхидеи сохраняют heading сценария, чтобы модель не уходила внутрь ствола.
- Для растений высота координат уточняется известным `GET_GROUND_Z_FOR_3D_COORD`; координаты яичных гнёзд остаются заданными composite-сценарием.
- Исправлена передача X/Y/Z и выходного буфера в `GET_SCENARIO_POINTS_IN_AREA`; первый `int32` читается со смещения 8, следующие — с шагом 8 байта. Lua-индексация таблицы тут не применяется.
- После сбора/поедания выбирается ближайший живой слот среди всех совместимых сценариев, а если `EVENT_LOOT_COMPLETE` ещё содержит исходную entity — используется её позиция. Координаты собранного слота обнуляются, чтобы исключить его из поиска и повторного спавна; остатки модели остаются до удаления композита при удалении игрока от точки.
- Ночной отказ от спавна уменьшает число записей в таблице точек.
- Событие поедания сбрасывается после завершения лута или по истечении таймаута.
- При остановке ресурса таблица собранных точек очищается.

## Индексы коллекционных цветов и птичьих яиц

При запуске сервер выбирает независимо два общих для игроков индекса от `0` до `5`: один для коллекционных полевых цветов, второй для птичьих яиц. Они могут совпасть. По умолчанию выбор случайный при каждом запуске ресурса и ежедневном обновлении; чтобы закрепить оба индекса, укажите в `shared/config.lua`:

```lua
Config.ForceCollectibleIndices = { flowers = 0, bird_eggs = 3 }
```

Для случайного выбора установите `Config.ForceCollectibleIndices = nil`. При фиксированной настройке указывайте оба поля целыми числами от 0 до 5: проверка корректности сейчас не выполняется. Координаты по видам и индексам находятся в `server/collectible_points.lua`: в таблице девять видов полевых цветов и девять видов птичьих яиц. Орхидеи, яйца кондора, яйца аллигатора и обычные травы этой таблицей не охватываются.

Сервер составляет список координат невыбранных индексов и отправляет его при загрузке персонажа. Клиент сравнивает координаты найденных scenario points со списком и пропускает совпавшие точки; новые точки по координатам из таблицы не создаются. Сравнение использует только X/Y, округлённые до трёх знаков. Поэтому фактическая работа зависит от совпадения справочных координат с координатами игровых точек; она требует проверки в RedM. Совпадающий XY разрешённой точки освобождает тот же XY и для других видов.

Ежедневно в 06:00 после очистки таблицы сервер заново выбирает индексы и отправляет новый список запретов подключённым игрокам. Созданные растения остаются на месте, чтобы не прерывать их сбор; сведения о собранных точках очищаются, а ранее отключённые сценарии снова включаются. Древесные гнёзда и раки полностью удаляются, их локальное состояние сбрасывается. Новый список запретов применяется при последующих сканированиях. При фиксированных индексах выбор остаётся прежним. Перезапуск также выбирает индексы и очищает `player_composites`. Для диагностики выбор индексов и число отключённых координат выводятся в серверную консоль при `Config.Debug = true`.

## Древесные яйца

Древесный спавнер работает отдельно от растений и обычных egg composites. Он ищет типы scenario point `WB_EGG_NEST_EAGLE`, `WB_EGG_NEST_CONDOR`, `WB_EGG_NEST_EGRET`, `WB_EGG_NEST_HAWK`, `WB_EGG_NEST_HERON`, `WB_EGG_NEST_SPOONBILL` в радиусе игрока и создаёт соответствующие модели гнезда и яйца. Модели и типы сверены с `net_bird_egg_*` и локальной таблицей scenario names.

При попадании в яйцо или гнездо с ammo type `ammo_arrow_small_game` и `AMMO_22` яйцо отделяется и получает физику. При попадании другим типом боеприпаса яйцо удаляется. Состояние сбитого, но ещё не подобранного яйца не сохраняется между выходами/перезагрузкой ресурса.

После успешного подбора яйца обработчик `EVENT_LOOT_COMPLETE` сопоставляет модель и entity яйца с созданным гнездом, а затем вызывает общий механизм наград. Виды древесных яиц добавлены в `Config.Composites` с ID `100–105`, поэтому для них можно настроить `rewards`, `lootExp`, параметры использования и опыт за использование. `CreateUseableItem()` автоматически регистрирует новые яйца как используемые; для отключения использования у записи поставьте `eat.use = false`. Ключ координат собранной точки записывается в `player_composites`, поэтому персонажу гнездо повторно не спавнится. Определения шести новых предметов находятся в `install/eng_items.lua` и `install/rus_items.lua`; их нужно перенести в список предметов `rsg-core` так же, как остальные предметы этого ресурса.

Параметры находятся в `config_tree_eggs.lua`: радиус/интервал поиска, лимит активных гнёзд, расстояние удаления, а также локальное смещение и разворот яйца внутри гнезда. Смещение `eggOffset` начальное; для точного совпадения с вашими моделями его можно подправить в игре. `Config.Debug = true` включает сообщения о найденных и созданных гнёздах в клиентской консоли.

## Раки и сбор в норах

Сбор раков работает отдельно от растений и птичьих яиц. В `shared/config_crayfish.lua` задано 17 нор с координатами и хешами декалей. Когда персонаж находится рядом с норой, ресурс создаёт у неё рака и точку сценария: игрок взаимодействует с норой, затем подбирает появившегося рака. Рак подсвечивается в «Орлином глазе». При удалении от норы объект и точка сценария удаляются; проверка расстояния выполняется раз в две секунды.

После подбора ресурс сопоставляет объект с норой и отправляет серверу запрос на выдачу награды. По умолчанию за один подбор выдаётся один `upgrade_fsh_bait_crayfish`. В норе случайно выбирается лимит от 1 до 3 сборов; после каждого подбора до исчерпания лимита рак может появиться снова. Полностью собранная нора сохраняется в `player_composites` для текущего персонажа. Частичный прогресс хранится только на клиенте и сбрасывается при выгрузке персонажа или перезапуске ресурса.

### Настройка

- `Config.EnableCrayFish` в `shared/config.lua` включает и выключает механику. Поле `Config.Crayfish.enabled` в `config_crayfish.lua` в текущей реализации не используется.
- `Config.Crayfish.Holes` содержит координаты и хеши декалей нор; `searchRadius` задаёт радиус появления и удаления объектов (по умолчанию 100.0).
- `crayfishZOffset` задаёт вертикальное смещение модели относительно земли, а `scenarioYOffset` — смещение точки сценария по оси Y. Модель и хеш сценария также указаны в `config_crayfish.lua`.
- `Config.Composites[200]` в `shared/config.lua` задаёт предмет, `spawn.minCol` и `spawn.maxCol` — диапазон числа сборов с норы, `pickupAmount` — количество предметов за один подбор, а `lootExp` — опыт. По умолчанию начисляется 2–3 опыта `herbalist` и 1 опыт `crafting`; функция `Config.serverUpdateExp` использует `rsg-statistics` и может быть заменена под вашу систему опыта.
- Использование рака самим ресурсом отключено через `eat.use = false`. Кулинария или изготовление наживки должны быть настроены отдельно.

Для награды добавьте определение `upgrade_fsh_bait_crayfish` из `install/rus_items.lua` или `install/eng_items.lua` в предметы `rsg-core`, а изображение `install/images/upgrade_fsh_bait_crayfish.png` — в каталог изображений инвентаря. Убедитесь, что имя предмета в конфигурации совпадает с именем в `Shared.Items`.

Записи об исчерпанных норах очищаются вместе с остальными записями `player_composites` ежедневно в 06:00 по времени сервера. После очистки таблицы состояние нор и список собранных точек обновляются и у уже подключённых персонажей. Для диагностики включите `Config.Debug = true`: сообщения о создании и сборе раков появятся в клиентской консоли.
