# rsg-composite

Отдельная версия ресурса с раздельными путями спавна растений и яиц.

## Установка

1. Скопируйте папку `rsg-composite` в каталог ресурсов сервера.
2. Отключите старый `rsg-composite`, затем добавьте `ensure rsg-composite` в конфигурацию сервера.
3. Убедитесь, что установлены зависимости `rsg-core`, `ox_lib` и `oxmysql`.

Новый ресурс использует собственные сетевые события и таблицу `player_composites`, поэтому сохранённые точки старого ресурса он не меняет. Таблица создаётся автоматически при старте; SQL-шаблон находится в `install/player_composites.sql`.

Обе версии регистрируют одни и те же usable items, поэтому не запускайте их одновременно: обработчик предмета может быть перезаписан одним из ресурсов.

## Что изменено

- Растения и яйца проходят через отдельные функции спавна; создание композита по-прежнему выполняет известный native `_CREATE_HERB_COMPOSITES`.
- Вариант гаторьей кладки выбирается случайно (3, 4 или 5 яиц), а количество награды берётся из ID выбранного варианта.
- Перед каждым native-вызовом проверяется общий лимит в 180 композитов. Учитываются только успешные ID; невалидный ID не передаётся в удаление.
- Спавн прекращается, если composite-ассет не загрузился.
- Исправлены верхняя граница количества слотов и расчёт X/Y по одному углу в радианах.
- Смещения древесных орхидей вынесены в таблицу по ID ресурса и сверены по названиям с оригиналом; для ванильного цветка сохранено отдельное смещение. Древесные орхидеи сохраняют heading сценария, чтобы модель не уходила внутрь ствола.
- Для растений высота координат уточняется известным `GET_GROUND_Z_FOR_3D_COORD`; координаты яичных гнёзд остаются заданными composite-сценарием.
- Исправлена передача X/Y/Z и выходного буфера в `GET_SCENARIO_POINTS_IN_AREA`; первый `int32` читается со смещения 8, следующие — с шагом 8 байта. Lua-индексация таблицы тут не применяется.
- После сбора/поедания выбирается ближайший живой слот среди всех совместимых сценариев, а если `EVENT_LOOT_COMPLETE` ещё содержит исходную entity — используется её позиция. Собранный слот получает оригинальный флаг `4096`, его composite handle удаляется отдельно, чтобы убрать остатки модели и не затронуть соседние растения.
- Ночной отказ от спавна уменьшает число записей в таблице точек.
- Событие поедания сбрасывается после завершения лута или по истечении таймаута.
- Остановка ресурса больше не очищает сохранённые данные игроков.

## Древесные яйца

Древесный спавнер работает отдельно от растений и обычных egg composites. Он ищет типы scenario point `WB_EGG_NEST_EAGLE`, `WB_EGG_NEST_CONDOR`, `WB_EGG_NEST_EGRET`, `WB_EGG_NEST_HAWK`, `WB_EGG_NEST_HERON`, `WB_EGG_NEST_SPOONBILL` в радиусе игрока и создаёт соответствующие модели гнезда и яйца. Модели и типы сверены с `net_bird_egg_*` и локальной таблицей scenario names.

При попадании в яйцо или гнездо с ammo type `ammo_arrow_small_game` и `AMMO_22` яйцо отделяется и получает физику. При попадании другим типом боеприпаса яйцо удаляется. Состояние сбитого, но ещё не подобранного яйца не сохраняется между выходами/перезагрузкой ресурса.

После успешного подбора яйца обработчик `EVENT_LOOT_COMPLETE` сопоставляет модель и entity яйца с созданным гнездом, а затем вызывает общий механизм наград. Виды древесных яиц добавлены в `Config.Composites` с ID `100–105`, поэтому для них можно настроить `rewards`, `lootExp`, параметры использования и опыт за использование. `CreateUseableItem()` автоматически регистрирует новые яйца как используемые; для отключения использования у записи поставьте `eat.use = false`. Ключ координат собранной точки записывается в `player_composites`, поэтому персонажу гнездо повторно не спавнится. Определения шести новых предметов находятся в `install/eng_items.lua` и `install/rus_items.lua`; их нужно перенести в список предметов `rsg-core` так же, как остальные предметы этого ресурса.

Параметры находятся в `config_tree_eggs.lua`: радиус/интервал поиска, лимит активных гнёзд, расстояние удаления, а также локальное смещение и разворот яйца внутри гнезда. Смещение `eggOffset` начальное; для точного совпадения с вашими моделями его можно подправить в игре. `Config.Debug = true` включает сообщения о найденных и созданных гнёздах в клиентской консоли.
